# Public APK native phone capture helper

This versioned public-app QA helper captures genuine Android phone screenshots from the already public WebSignly Player1.0.3/code4 APK. It contains no application source, signing material, private repository references, account credentials, or organization pairing inputs. Its emulator capture has not yet been executed; the offline checks establish guard/conversion behavior only.

Publish exactly four files: `README.md`, `pins.json`, `capture-phone.py`, and `.github/workflows/capture-phone.yml`. The `metadata-*.xml` snapshots alongside this local review pack stay local and are not required or published. Self-tests create catalog fixtures in memory and never read those snapshots. At runtime the helper fetches and validates the actual official catalogs and exact reviewed license; synthetic fixture terms cannot authorize SDK installation.

The proposed device is a Pixel 2 portrait profile, 1080×1920, running the official API 36 Google APIs x86_64 phone image with KVM. A Google Play image/account is unnecessary: these are genuine Android screenshots of the public standalone APK's pairing and privacy surfaces, which are shared with the Play build. These images do not establish installation from Google Play or verify the Play-only navigation guard. The helper never captures channel-specific settings.

On October27,2026 a bounded public-metadata-only HTTPS check of Google's SDK `addons_list-7.xml` discovered `sys-img/google_apis/sys-img2-5.xml`. Its stable API36 Google APIs x86_64 image is revision7, requiring emulator35.4.9 or newer. The current stable emulator is37.2.12. `pins.json` records the exact revisions, dependencies, archive size/SHA1 and freshly retrieved XML SHA256 values; the local XML snapshots are retained separately for review. Both packages reference the exact already reviewed `android-sdk-license` text. No additional license is accepted. Changed package/channel/archive/terms fails closed at runtime.

Google's catalog publishes **SHA1**, not SHA256, for the1,895,447,397-byte phone archive. No SDK package has been downloaded to compute an independent SHA256. The helper pins Google's published archive metadata and uses SDKmanager's archive verification, then checks installed package revisions. The SHA256 values in `pins.json` identify the XML metadata, not the un-downloaded archive. Do not describe them as archive SHA256.

The reviewed raw license SHA256 remains `1f8729233617b193fd619213792ae16a41b95d2bbbf525dfe66998252ba68b16`. Only after that exact check, the helper applies the SDK's verified `TrimStringAdapter.unmarshal` normalization and writes the SDK acceptance SHA1 `24333f8a63b6825ea9c5514f83c2829b004d1fee`. The normalization and hash were cross-checked against the actual cached SDK class using the same public XML; this accepts the same agreement, not new terms. Raw/outer-trimmed text hashes are not written as acceptance tokens.

Root must first deploy the public 1.0.3/code4 APK and verify its URL serves exactly 1,535,256 bytes with SHA256 `2dde063ecbb5cebfcebca67e63a56ef83671934eb22895801071765fb7e0e549`. Redirects, unexpected APK bytes/certificate/package/version, image revisions, terms or archive metadata fail closed.

Only an owner-started `workflow_dispatch` in a public repository may run. Both acknowledgement inputs default false; no push/PR trigger exists. The owner must verify the selected standard public Linux runner is free. This helper does not authorize a private-repository or larger paid runner. Maximum job time is22 minutes; script deadline18 minutes; artifact retention3 days. It requires KVM and at least4 CPUs, with no software-emulation fallback. No dispatch is authorized merely by preparing these files.

No Gradle build, private checkout, production signing, or email occurs. The APK may create one unclaimed anonymous pairing challenge and fetch the public privacy policy/resources. It never submits a code to an organization, enters an account, publishes content, or records playback.

The script captures only actual `adb exec-out screencap -p` pixels after native foreground and UI assertions. Original PNGs are preserved under `raw/`; upload PNGs remove alpha only if every pixel is fully opaque, otherwise fail. RGB conversion preserves every visible pixel and adds no UI. Outputs are pairing, privacy, and sanitized evidence. Raw logs, XML dumps, SDK state and APK are excluded from uploaded artifacts. Only the emulator process group and this helper's separate ADB port are stopped.

For a failure before any APK-install attempt, with no organization paired and the owned emulator process group confirmed stopped, the artifact may also retain `boot-output-redacted.txt`: at most16KiB of official SDK startup output, with JWT/token/key/UUID/MAC/opaque identifiers, URLs, paths, terminal escapes and control characters redacted. This is never device/app logcat. It records fixed startup classifications, the emulator exit code/deadline state, and free disk bytes before launch/after failure. No GPU, OS or acceleration fallback is attempted. If installation was attempted or emulator stop cannot be confirmed, the text is not retained.

SDKmanager receives an explicit SDK root. License or package refusal is rejected even if SDKmanager exits0; fixed warning classifications are recorded without publishing raw stdout. Each expected installed package's metadata has a distinct validation stage and identity. A missing `package.xml` fails closed even when legacy `source.properties` exists; its existence is diagnostic only. No legacy fallback is used.

The isolated `ANDROID_AVD_HOME` and `ANDROID_USER_HOME` directories are created before any SDK process: avdmanager ignores an AVD home that does not already exist, whereas the emulator uses the configured location. The SDK creates the AVD with an explicit owned data path. Before launch, the helper validates the generated registry `.ini`, exact data/config path, approved API36 Google APIs x86_64 image and ABI, and verifies the emulator lists that AVD. It never creates a registry file by hand. Evidence records fixed identity flags without filesystem paths.

SDK license backups and generated-license quarantine use unique adjacent siblings of the SDK's license directory, so restoration does not cross filesystems. Only the reviewed license hashes are active during installation. SDK-created files are preserved outside that active directory, and the runner's original license directory is restored. Cleanup errors retain the primary installation failure; a restoration failure after otherwise successful installation also stops the run. Sanitized errors report exception class/errno, operation phase, command exit code, and a fixed SDK failure classification. Raw command output, exception messages and untrusted paths are not published. Expected SDK-relative metadata paths are fixed helper constants.

Offline checks: `python3 -I -B capture-phone.py --plan` and `--self-test`. These modes do not download packages, contact providers, start ADB, or start an emulator. The self-test covers74 synthetic checks, including all five PNG filters, exact RGB/RGBA conversion, translucent/invalid image rejection, native UI/foreground checks, catalog revision/dependency/archive rejection, rejection of fixture terms by the real runtime license default, seven SDK adapter black-box normalization fixtures, license-directory restoration with extra SDK files, preservation of primary errors during cleanup failure, restoration failure after success, zero-exit SDK refusal, exact installed-metadata identity, boot-output bounds/redaction, pre-install/stopped-process retention gates, AVD directory/registry/path/image/ABI validation, and diagnostic redaction. Only the owner's final manual workflow dispatch authorizes `--run`.
